## ШАГ 1. Аудит позиционирования и SEO

### 1.1 Текущее состояние

**Текущий Title:**

```
Umbot Flow Editor — визуальный конструктор чат-ботов
```

**Текущий Description:**

```
Бесплатный онлайн-конструктор чат-ботов для Telegram, Алисы, VK и других платформ. Визуально создавайте ботов без программирования, экспортируйте код и запускайте.
```

**Проблемы:**

1. **Некорректное позиционирование.** Title и Description позиционируют продукт как "визуальный конструктор чат-ботов без программирования" — это звучит как самостоятельный SaaS-сервис. На деле это **генератор JSON-конфигураций** для TypeScript-фреймворка umbot. Пользователь скачивает JSON и генерирует код через CLI.

2. **Разрыв ожиданий.** Человек приходит, видит "конструктор чат-ботов без программирования", ожидает облачный хостинг и一键-деплой. Получает JSON-файл и командную строку. Это критическая проблема конверсии.

3. **SEO-позиция невыгодна.** Конкурировать с чат-бот конструкторами (Chatfuel, BotMother, SendPulse) бесполезно — у них домены, бэклинки, бюджет. Нужна ниша: "визуальный редактор для umbot", "визуальный генератор конфигураций ботов для Telegram/Алисы/VK".

4. **Отсутствие keywords-meta** (не критично для Яндекса/Google, но мета-тег keywords есть — он содержит generic-фразы).

### 1.2 Семантическое ядро (Long-Tail)

Целевая аудитория — **русскоязычные TypeScript/Node.js разработчики**, которые уже знают umbot или ищут способ быстро создать бота для нескольких платформ.

**Приоритетные long-tail запросы:**

| Запрос                                                     | Интент  | Сложность |
| ---------------------------------------------------------- | ------- | --------- |
| "визуальный редактор навыков алисы с экспортом кода"       | Высокий | Средняя   |
| "конструктор бота вк с выгрузкой кода на typescript"       | Высокий | Средняя   |
| "umbot json builder визуальный"                            | Точный  | Низкая    |
| "генератор бота telegram из json конфигурации"             | Высокий | Средняя   |
| "визуальный флоу-редактор для чат-ботов с экспортом в код" | Высокий | Низкая    |
| "создать бота для алисы визуально с генерацией typescript" | Высокий | Низкая    |
| "редактор конфигурации umbot фреймворка"                   | Точный  | Низкая    |
| "визуальный конструктор мультиплатформенных ботов开源"     | Средний | Низкая    |

**Стратегия:** Не конкурировать с общими "конструкторами ботов", а занять нишу "визуальный редактор конфигураций для umbot/framework с генерацией TypeScript-кода".

### 1.4 Страница JSON-спецификации: нужна ли?

**Вердикт: Да, однозначно.**

**Почему:**

1. Файл `JSON_FORMAT.md` уже существует и содержит 540 строк детальной спецификации — он не используется для привлечения трафика.
2. Разработчики, которые ищут "umbot json format", "umbot конфигурация формат", "как выглядит json дляUMBOT" — это готовые лиды.
3. Отдельная страница с JSON Schema, примерами кода и документацией может занять позиции в поиске по точным запросам.
4. Ссылка со страницы конструктора на документацию повышает экспертность (E-E-A-T).

## ШАГ 2. UX/UI и Developer Experience (DX)

### 2.1 Проблема онбординга: "что делать с JSON?"

**Текущее состояние:** После нажатия "Проверить и экспортировать" пользователь видит модальное окно с:

- Результатом валидации
- Кнопкой "Скачать flow.json"
- Списком из 6 шагов (текстовые инструкции)

**Проблемы:**

1. Инструкции длинные (6 шагов), junior-разработчик может потеряться.
2. Шаг 2 ("Установите Node.js") и шаг 4 ("Откройте PowerShell") — это инструкции для тех, кто никогда не работал с CLI. Но текст мелкий и неструктурированный.
3. Нет "быстрого пути" — пользователь вынужден читать всё подряд.
4. Нет визуального фидбека: "ваш JSON скачан, вот команда".

**Рекомендуемые UX-решения:**

#### Решение A: "3 шага к запуску" (рекомендуется)

Заменить текущий список из 6 шагов на компактный чек-лист из 3 шагов с явным акцентом:

```
┌─────────────────────────────────────────────────┐
│  ✅ JSON готов! Ваши下一步:                      │
│                                                   │
│  ☐ Скачайте файл flow.json                       │
│  ☐ Откройте терминал в папке с файлом            │
│  ☐ Выполните:                                    │
│                                                   │
│  ┌──────────────────────────────────────────┐    │
│  │ npx umbot create from-flow flow.json     │    │
│  └──────────────────────────────────────────┘    │
│                                                   │
│  [📋 Копировать команду]                          │
│                                                   │
│  После этого в папке my-bot будет готовый        │
│  TypeScript-проект. Запустите npm install &&     │
│  npm run dev для проверки.                       │
│                                                   │
│  Не знаете что делать с кодом? Отправьте папку   │
│  my-bot вашему разработчику.                     │
└─────────────────────────────────────────────────┘
```

**Почему это лучше:**

- Команда в отдельном блоке с моноширинным шрифтом — её можно скопировать одним кликом.
- Only 3 steps instead of 6 — cognitive load reduced.
- Кнопка "Копировать команду" — мгновенный фидбек.
- Текст "Не знаете что делать?" — safety net для нетехнических пользователей.

#### Решение B: Интерактивный чек-лист (дополнение к A)

Добавить в модальное окно интерактивный чек-лист:

```
□ Файл скачан
□ Node.js установлен (проверить: node -v в терминале)
□ Команда выполнена
□ Проект создан в папке my-bot
```

Пользователь кликает по каждому шагу — он отмечается как выполненный. Это даёт ощущение прогресса.

#### Решение C: Кнопка "Скопировать команду" на тулбаре

Добавить в тулбар кнопку-значок (📋), которая копирует полную команду `npx umbot create from-flow <name>.json` в буфер обмена. Это позволяет пользователю не открывать экспорт-диалог каждый раз.

### 2.2 Связь блоков → JSON → TS-код

**Текущее состояние:** Пользователь собирает блоки на холсте, но не видит:

- Какой JSON будет сгенерирован из текущей схемы
- Какой TypeScript-код будет сгенерирован из JSON

**Рекомендации:**

#### Решение A: Превью JSON-экспорта (приоритет: Med)

Добавить в панель свойств (или в экспорт-диалог) вкладку/секцию "JSON Preview", которая показывает JSON для выделенного узла в реальном времени. Пользователь видит:

```
Узел: Команда "greeting"
JSON:
{
  "type": "command",
  "name": "greeting",
  "slots": ["привет"],
  "response": { "text": "Привет!" }
}
```

Это снимает "магию" — пользователь понимает прямую связь: холст → JSON.

#### Решение B: Документация "Как генерируется код" — в `src/docs/` (приоритет: Med)

Подробное описание паттернов генерации кода (addCommand, addStep, switch-case, HTTP) выносится в отдельную страницу документации в `src/docs/`. На странице конструктора — ссылка на неё. Это контент для программистов, которые хотят понять механику, но не перегружает основной интерфейс.

### 2.3 Отсутствие "магии"

**Текущая проблема:** Нигде в интерфейсе не объясняется:

- Что формат JSON стабилен (из pr2.md: "формат JSON стабилен, возможны только аддитивные изменения")
- Что это не SaaS — данные хранятся локально
- Что CLI работает offline, без регистрации

**Рекомендации:**

1. На странице конструктора (или в Help-модалке) добавить секцию "Как это работает":

    ```
    Визуальный редактор → JSON-конфигурация → CLI → TypeScript-проект → Ваш сервер
    ```

    С визуальной схемой-диаграммой.

2. В footer или в Help: "Формат JSON стабилен. Обновления редактора не ломают ранее созданные конфигурации."
